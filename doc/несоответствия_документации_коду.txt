--------------------------------------------------------------------------------
1. Процесс регистрации (doc/Client registrations.md, doc/topics/Topic 'reg'.md
   vs src/uclient/hub.py)
--------------------------------------------------------------------------------
Документация описывает полный процесс: клиент отправляет MAC на /reg →
сервер отвечает /{hub}/time → клиент отправляет /{hub}/info.

Код пропускает этот процесс — регистрация через /reg обойдена (TEMP bypass):
    # hub.py, строка 81
    self.state = self.REG_SEND_SRV_DATA  # TEMP: bypass /reg registration
    # hub.py, строка 201
    self.state = self.REG_SEND_SRV_DATA  # TEMP: bypass /reg registration
    # hub.py, строка 373
    self.state = self.REG_SEND_SRV_DATA  # TEMP: bypass /reg registration
Метод __send_reg() существует, но фактически не вызывается при подключении.

--------------------------------------------------------------------------------
2. Значение lifetime по умолчанию (doc/topics/hub/Topic 'lifetime'.md
   vs src/uclient/hub.py)
--------------------------------------------------------------------------------
Документация: "By default lifetime is set to 60 sec".

Код: self.lifetime = 3 при инициализации (строка 83), и только после
регистрации становится 60.

--------------------------------------------------------------------------------
3. Таймаут UART (doc/Example app - UART bridge.md vs src/consts.py)
--------------------------------------------------------------------------------
Документация: "Internally TTY have 10ms as maximum interval between symbols".

Код: UART_TIMEOUT_MS = 20 (20 мс, строка 9).

--------------------------------------------------------------------------------
4. Ответ на user/add (doc/topics/hub/device/Users topics.md
   vs src/uclient/userdev.py)
--------------------------------------------------------------------------------
Документация: "As return value, device should send user number".

Код: отправляет "OK" вместо номера пользователя:
    # userdev.py, строка 182
    self.pub_dev(topic, aes.encrypt('"OK"'.encode(), self._device_id))

--------------------------------------------------------------------------------
5. Формат user/remove (doc/topics/hub/device/Users topics.md
   vs src/uclient/userdev.py)
--------------------------------------------------------------------------------
Документация: "need to send every odd byte from UID in a ciphered way".

Код: расшифровывает и сравнивает полный UID:
    # userdev.py, строка 215
    uid = aes.decrypt(base64.b64decode(msg), usr.uid)

--------------------------------------------------------------------------------
6. Генерация device_id (doc/Users.md vs src/config.py)
--------------------------------------------------------------------------------
Документация: "Device identificator (did) will be generated from a WIFI name
and WIFI password via sha256... Or through the same sha256 from number of phone".

Код: генерируется из MAC-адреса:
    # config.py, строка 33
    self.device_id = hashlib.sha256(self.mac.encode()).digest().hex()

--------------------------------------------------------------------------------
7. Ответы fw_url во время загрузки (doc/topics/hub/device/Firmware update topics.md
   vs src/uclient/fwupd.py)
--------------------------------------------------------------------------------
Документация: "Total downloaded size while be sent as response WHILE downloading
is ongoing" (пример показывает ответы 512, 1024, 1536... по мере загрузки).

Код: отправляет размер только ОДИН РАЗ после завершения загрузки:
    # uclient/fwupd.py, строка 35
    self.pub_dev(topic, total)

--------------------------------------------------------------------------------
8. Бит 0 глобальных permissions (doc/Users.md vs src/uclient/user.py)
--------------------------------------------------------------------------------
Документация: бит 0 — rfu (зарезервирован).

Код: бит 0 определён как USER_ACL_REG_READ = const(1) (строка 15) —
не соответствует документу.

--------------------------------------------------------------------------------
9. Аппаратная платформа (doc/Hardware and firmware summary.md vs код)
--------------------------------------------------------------------------------
Документация: "ESP32-WROOM-32D MCU" и "SIM800D modem".

Фактически в коде: используется ESP32-C3 (esp32.json, build_fw_esp32c3.sh,
doc/Example app - UART bridge.md упоминает ESP32-C3) и модем A76XX
(src/hw/esp32/ppp.py, doc/A76XX-Series_AT_Command_Manual_V1.06-4.pdf).

--------------------------------------------------------------------------------
10. Пустые/неполные документы
--------------------------------------------------------------------------------
- doc/Device filesystem.md — файл пустой (1 строка), но на него ссылаются
  doc/Firmware update.md и doc/UEBA bootloader.md.
- doc/Upgrade via web-page (FW_UPD).md — содержит только 1 строку
  ("After start device, device will connect to the already configured network"),
  хотя тема подробно описана в doc/Firmware update.md.

--------------------------------------------------------------------------------
11. Опечатка в doc/topics/hub/Topic 'ping'.md
--------------------------------------------------------------------------------
Документация: "To get version string need to send word 'version' into
/{HUB}/ping topic" — это опечатка, должно быть 'ping'.
Код (__ping_hnd) корректно ожидает 'ping'.

--------------------------------------------------------------------------------
12. Описание формата событий (doc/topics/hub/device/Events topic.md)
--------------------------------------------------------------------------------
Текст документации: "Inside JSON object: tm - Event unixtime".

Примеры в той же документации и код (evtdev.py, строка 46): используют ключ ts:
    buf = [{'ts': evt[1].tm, 'r': reg, 'v': evt[2]}]
Внутреннее противоречие в документе (текст vs примеры).

--------------------------------------------------------------------------------
13. Незавершённые пункты в doc/tasks.md
--------------------------------------------------------------------------------
Отмечены как невыполненные, но код частично реализован или наоборот:
- "check acls and follow permissions" — в userdev.py нет проверки ACL
  (списка доступа) при записи регистров, только глобальные permissions.
- "Error topics tests" — нет тестов.
- "Batch transfers" — не реализовано.
- "Current time register (/3?)" — не реализовано.
- "handling disconnections" (модем) — не реализовано.
- "sending sms from uart/ble side" — не реализовано.

--------------------------------------------------------------------------------
14. Фиксированный CLIENT_ID (src/uclient/mqtt_transport.py)
--------------------------------------------------------------------------------
    CLIENT_ID = "esp32-c3-mpy-test"  # строка 24
Жёстко заданный client ID не документирован и может конфликтовать с AWS IoT
(должен соответствовать thing name).

--------------------------------------------------------------------------------
15. Временный тестовый код в src/main.py
--------------------------------------------------------------------------------
Блок эмуляции UART 3KB (строки 193–226) — временный отладочный код, не описанный
в документации. Также wlan_est() закомментирован в main() (строка 333:
wlan_init = False # wlan_est(modem_init)), хотя документация описывает работу
через Wi-Fi.

--------------------------------------------------------------------------------
16. Странные DEBUG-комментарии в src/config.py
--------------------------------------------------------------------------------
Строки 39–41 содержат комментарии "DEBUG: This line is commented out..." —
но код при этом АКТИВЕН (не закомментирован). Это артефакт, вводящий
в заблуждение.
